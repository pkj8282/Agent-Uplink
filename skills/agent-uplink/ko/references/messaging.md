# 메시지 쓰기와 기다리기

## 쓰기

- 첫 줄에 무슨 메시지인지 적습니다: `[Handoff 2/3]`, `Task 5 commit abc1234`, `Question:`, `Review: Task 4 — approved`.
- 메시지 하나에 주제 하나. 긴 내용은 번호를 붙여 나누고(`1/3`), 각각 따로 읽어도 통하게 합니다.
- 상태는 한 줄로. 긴 내용은 파일에 쓰고 경로를 보냅니다(모든 세션이 같은 PC에 있습니다).
- 다른 세션이 확인할 수 있는 것을 넣습니다: 커밋 해시, 줄 번호가 붙은 파일 경로, 테스트 명령과 결과.
- 내 맥락을 전혀 모르는 사람이 읽는다고 생각하고 쓰세요 — "말한 대로", "그 버그" 같은 표현 금지.
- 비밀 정보, 토큰, 비밀번호는 절대 보내지 마세요: 메시지는 디스크에 남고 로그 뷰어에 보입니다.
- DM에 답하려면 `open_dm(peer)`를 다시 부르세요. 같은 채널을 돌려줍니다. 받은 항목에는 채널 ID가 아니라 채널 이름과 보낸 이(`[#계획-구현 계획]`)가 보입니다. `list_dms`는 상대마다 채널 ID와 설명을 보여 주므로, 다른 프로젝트의 같은 이름 역할도 가려낼 수 있습니다.
- 프로젝트 이야기는 `lobby`에 쓰지 말고 프로젝트 채널을 쓰세요.

## 기다리기

- 답을 기다리는 쪽이 기다립니다. `timeoutMs`를 최대 120000으로 `wait`를 부르세요. `(no new messages)`는 아직 아무것도 오지 않았다는 뜻이니 다시 부르세요.
- 질문의 답을 기다릴 때: 약 10분 동안 답이 없으면 `list_accounts`를 확인하세요. 상대 세션이 오프라인이거나 여전히 조용하면 계속 기다리지 말고 사용자에게 알리세요.
- 팀으로 일할 때: 보고한 뒤에도 다음 요청을 계속 기다립니다. 작업이 끝났다는 말을 듣거나, 내 채널들에 약 30분 동안 메시지가 없으면 멈추고 — 사용자에게 보고한 뒤 턴을 끝냅니다. 사용자가 다른 한도를 정할 수 있고, 그쪽이 우선합니다.
- `wait`와 `check`는 내가 볼 수 있는 모든 채널의 메시지를 돌려줍니다. 나에게 온 것은 처리하고, 나머지는 버리지 말고 기록하거나 사용자에게 알리세요 — 한 번만 전달됩니다.
- `wait` 호출마다 모델 턴이 하나씩 들고 토큰을 씁니다. Claude Code에서 오래 한가할 때는 계속 기다리는 것보다 `/loop`로 주기적으로 확인하는 편이 쌉니다.
